# 三种模式的实际差异（示例对比）

同一段原始字幕，在三种 mode 下的分段和讲解深度：

> 原始字幕（节选）：
> `0:29 周期研究的是什么` `0:31 从长时间轴上` `0:32 周期就是在研究资源的定价问题`
> `0:35 生产力的发展` `0:36 就是在货币与生产中体现出来的` `0:39 最终都会以价格被表示出来`

## mode = s（时间表对照，默认）

**分段**：约 60-120 秒一段，全片 11-14 段（以 12 分钟视频计）

**讲解深度**：每段 2-3 个解读段落，覆盖该段所有要点。

```json
"0": {
  "head": "理论内核：价格是「货币」和「产能」两股力量拉锯的结果",
  "read": [
    "这一段是全片的地基，而且它是站得住的。翻译成大白话：产能＝世界上有多少东西可买；货币＝世界上有多少钱在追这些东西。",
    "钱多货少 → 涨价；货多钱少 → 跌价。这就是最基础的货币数量论。",
    "但请注意：到这一步为止，他讲的全是「价格由什么决定」，一个字都没提「周期」。"
  ],
  "flags": [{"kind":"ok","label":"可以接受","text":"供需 + 货币决定长期价格，这个框架没有争议。"}]
}
```

**适用**：绝大多数情况。用户拿到就能从头读到尾。

## mode = k（关键节点讲解）

**分段**：100-200 秒一段，全片 5-7 段。低信息密度段（客套、重复、跑题）会被略过或合并。

**讲解深度**：只对高分段的做详细解读，低分段一句话带过或直接跳过。

```json
"0": {
  "head": "（0:00-2:04）开场 + 理论内核 + 五轮周期表",
  "read": [
    "这三块本身是连贯的：先声明方法论（讲故事不是做证明），
     再给理论内核（货币 vs 产能），最后给时间骨架（五轮周期）。",
    "**关键判断**：理论内核站得住，时间骨架是硬加的。分界点在 1:19。"
  ],
  "flags": [{"kind":"warn","label":"分界线在这","text":"从「常识」跨到「理论」，就在这一句。"}]
}
```

**强制要求**：`k` 模式必须在 `lead` 里明确告诉用户**你跳过了哪些内容、为什么跳**。
否则用户会以为全片只有这些。

```json
"lead": {
  "items": [
    "本页跳过了 3:45-4:10 的俄国战争叙述（与本主题无关）",
    "也合并了 10:57-11:30 的并购潮讨论（信息重复）"
  ]
}
```

**适用**：视频 >40 分钟；或者用户明确说"只要重点"。

## mode = f（逐片讲解）

**分段**：40-90 秒一段，全片 16-25 段。**不跳过任何内容**，包括客套和跑题。

**讲解深度**：每段 1-3 个解读段落。哪怕这段只是客套，也要说明"这段是客套，可以快进"。

```json
"0": {
  "head": "开场 26 秒：他先把自己会被骂的两个方向堵掉了",
  "read": [
    "这是一个很标准的开场技巧：先把两种可能的批评提前说出来（太抽象=无聊，太具象=庸俗）。
     听的人会觉得「他很清醒」，从而放下防备。",
    "但这句话对你有实际用处——它等于主动声明了方法论：他要用故事和事件来讲。==也就是叙事，不是证明。=="
  ]
}
```

**适用**：用户说"精细""不漏""全片""每一段"。或内容密度极高（如技术讲座、论文讲解）。

## 选哪个：判断表

| 用户说 | 视频时长 | 推荐 |
|---|---|---|
| 没说 / "帮我讲解" | 任意 | `s` |
| "只要重点" "太长了" | >30min | `k` |
| "精细" "不漏" "逐段" "全片" | 任意 | `f` |
| 没提粒度 | >60min | 先问一句，或默认 `k` 并说明可切 `s` |

**默认 `s`**，因为它是最平衡的：信息不丢，可读性好，用户想深入可以再要 `f`。

## 实现细节

三种模式共用同一套脚本，只有分段参数不同：

```python
MODE_PRESETS = {
    "s": {"max_chars": 240, "gap": 2.5},
    "k": {"max_chars": 420, "gap": 3.5},
    "f": {"max_chars": 170, "gap": 2.0},
}
```

`max_chars` 控制段落长度上限，`gap` 控制"停顿多久算断段"。

分段后还有一道 `merge_short_tail` 处理：把 <8 秒的短段并入前一段，
避免片尾"请点赞订阅"单独成段。
