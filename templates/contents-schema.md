# contents.json 结构规范

这个文件是**讲解内容的唯一来源**，`render.py` 只负责排版，不做任何内容判断。

写完后用 `render.py` 渲染；要改内容只改这个 json 再重渲染，不必重跑取字幕流程。

## 完整示例

```json
{
  "title": "视频标题（可用中文改写，不必照抄原标题）",
  "subtitle": "一句话说明这集在讲什么、为什么值得看。支持 **粗体** 和 ==高亮==。",
  "mode": "s",

  "lead": {
    "intro": "开场引导。可省略。",
    "items": [
      "**要点一**：用一句话说清",
      "**要点二**：……"
    ],
    "onesent": "一句话总结全文（会显示在虚线框里）"
  },

  "terms": [
    {"zh": "康波周期", "en": "Kondratiev wave", "at": "0:02",
     "def": "苏联经济学家提出的 50-60 年长周期理论。外行一看就懂的解释。"}
  ],

  "segments": {
    "0": {
      "head": "这一段的小标题：说清楚它在这集里的作用",
      "read": [
        "第一段解读。用大白话，不要复述原文。",
        "第二段解读。**重点**可以加粗，==特别关键==的加高亮。"
      ],
      "flags": [
        {"kind": "ok",   "label": "可以接受", "text": "这个框架没有争议。"},
        {"kind": "warn", "label": "要打折",   "text": "方向对，但量级是编的。"},
        {"kind": "err",  "label": "有问题",   "text": "这里有明显的逻辑漏洞。"}
      ],
      "extra_table": {
        "headers": ["周期", "年份", "技术"],
        "rows": [["第一轮", "1782-1845", "蒸汽机"]]
      },
      "addon": "补充说明。会显示为虚线分隔的小字。"
    }
  },

  "notes": [
    {"title": "1. 小标题", "paras": ["段落一。", "段落二。"]}
  ],

  "facts": [
    {"n": "15.68%", "l": "美国 10 年期国债收益率历史峰值<br>1981 年 10 月"}
  ],

  "recap": {
    "items": ["用法一", "用法二"],
    "onesent": "收尾的一句话判断。"
  },

  "xhs": {
    "title": "小红书标题（20 字内）",
    "body": "正文。\n换行用 \\n。",
    "tags": ["标签1", "标签2"]
  },

  "footer": "数据来源、处理方式、免责声明。"
}
```

## 字段详解

### `segments` 的键
用**段索引字符串**（`"0"`, `"1"`, ...）或**时间码**（`"1:23"`）。索引更稳。

段数与 `segments.json` 的 `count` 必须一致。少了会渲染成"（未填写小标题）"。

### `flags.kind` 的选择标准

| kind | 含义 | 什么时候用 |
|---|---|---|
| `ok` | 可接受 | 符合主流共识、可查证的事实、正确的逻辑 |
| `warn` | 要打折 | 方向对但夸大、结论依赖未证实的前提、有更复杂的解释 |
| `err` | 有问题 | 事实错误、逻辑自相矛盾、不可证伪、幸存者偏差 |

**判断原则**：宁可标 `warn` 不要标 `ok`。标 `ok` 意味着你替内容背书。

如果整段确实是纯事实陈述（比如"1971 年布雷顿森林体系崩溃"），可以只用一个 `ok`。

### `read` 的写法

**不要这样写**（等于没解读）：
> 作者指出康波周期分为四个阶段，分别是复苏、繁荣、衰退和萧条。

**要这样写**（解释含义）：
> 这四个阶段你可以先粗暴理解成春夏秋冬。真正要记住的不是名字，而是
> **每个阶段对应什么样的价格行为**——复苏期波动小、繁荣期平稳、
> 衰退期剧烈、萧条期冲高回落。

判据：**如果一句解读把原文的术语换掉之后信息量没有增加，就是废话。**

### `terms.at`
填该词**首次出现**的时间码。这样用户听到这个词时能对上。

### `facts`
只放**可查证的数字**，不要放观点。每个数字都应能在页脚找到来源。

## 模式差异

`mode` 字段影响页头标签显示（"时间表对照"/"关键节点讲解"/"逐片讲解"）。
内容详略由你自己控制：

- `s`：每段 `read` 2-3 段，`flags` 0-2 个
- `k`：只写高分段的详细解读，低分段可合并
- `f`：每段 `read` 1-3 段，不跳过任何段，宁可短也要写
